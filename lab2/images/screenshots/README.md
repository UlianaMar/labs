# Лабораторная работа №2

## Анализ веб-приложения и клиент-серверного взаимодействия

## 1. Исследуемая информационная система

Для выполнения лабораторной работы был выбран сервис Wildberries и пользовательский сценарий: поиск товара и просмотр карточки.

Wildberries — это крупный международный маркетплейс, позволяющий покупать товары различных категорий.

В ходе исследования были выделены следующие основные компоненты:

- браузер пользователя;
- интерфейс сайта (frontend);
- клиентский JavaScript, который управляет поиском и отображением карточек;
- API-сервис, принимающий запросы от клиента;
- backend, реализующий обработку данных;
- хранилище данных, в котором сохраняются товары, пользователи и заказы;
- внешние сервисы и ресурсы (CDN, аналитика, загрузка статических файлов).

### 1.1. Сценарий исследования

Исследуемый сценарий:
1. Открытие главной страницы Wildberries.
2. Ввод поискового запроса в строку поиска.
3. Просмотр списка найденных товаров.
4. Клик по конкретному товару.
5. Переход на страницу карточки товара.
6. Изучение описания, характеристик и отзывов.
7. Проверка визуального результата.

## 2. Анализ HTTP-запросов

Были замечены следующие типы HTTP-запросов:
- GET-запросы для загрузки JSON-файлов конфигурации и статических ресурсов;
- POST-запросы для отправки данных на сервер после действия пользователя (аналитика);

## 3. Анализ HTTP-ответов

Для анализа были выбраны запросы, связанные с загрузкой статики и API.

### 3.1. Пример анализа ответа на запрос

Был получен ответ со статусом 200 OK. Это указывает на успешную обработку запроса сервером.

Основные наблюдаемые заголовки:
- `content-type: text/html; charset=utf-8` (или `application/json` для API);
- `server: wbaas` — указывает на использование внутреннего сервера Wildberries;
- `x-cache-status: HIT` — запрос был обслужен из кэша CDN;
- `content-encoding: br` — данные сжаты с помощью Brotli для экономии трафика.

## 4. Анализ параметров и передаваемых данных

При выполнении поиска браузер передавал серверу информацию, которая позволяла понять, какой товар ищет пользователь.

### 4.1. Параметры запроса

В запросах, связанных с поиском, можно было выделить следующие типы параметров:
- В URL (query string): поисковый запрос и номер страницы.
- В заголовках: время операции, версия браузера, тип передаваемых данных (Content-type).
- Идентификатор сессии (внутри cookie).

### 4.2. Анализ Payload POST-запроса

Для POST-запроса `frontend-analytics` была открыта вкладка **Запрос (Payload)**. Установлено, что данные передаются в теле запроса в закодированном (сжатом) виде. Это делается для экономии трафика и сокрытия внутренней логики аналитики.

## 5. Анализ cookies

Cookies используются в веб-приложениях для хранения небольших данных, которые браузер должен отправлять серверу при последующих запросах.

### 5.1. Что было обнаружено

Для исследуемого сайта были просмотрены cookies через вкладку Application / Storage. 

| Имя cookie | Домен | Срок действия | Назначение | Флаги |
|------------|-------|---------------|------------|-------|
| `device_id` | `.wildberries.ru` | ~1 год | Идентификация устройства | Secure, HttpOnly, SameSite=Strict |
| `x_wbaas_token` | `.wildberries.ru` | Сессия | Токен авторизации | Secure, SameSite=None |

### 5.2. Анализ результатов

Наблюдаемый факт: на сайте используются cookies, которые отправляются вместе с запросами к домену сервиса. Токен `x_wbaas_token` содержит JWT (JSON Web Token), что подтверждает его использование для авторизации.

## 6. Взаимодействие Frontend, API и Backend

Для выбранного пользовательского сценария важным является понимание цепочки событий от действия пользователя до визуального обновления интерфейса.

### 6.1. Последовательность событий

- Пользователь
- Интерфейс сайта
- JavaScript / frontend-логика
- HTTP-запрос к API
- Backend-сервис
- Обработка данных
- HTTP-ответ
- Обновление интерфейса
- Пользователь видит результаты поиска

### 6.2. Конкретное действие

Рассмотрим действие: пользователь вводит запрос в строку поиска и нажимает Enter.

1. Пользователь взаимодействует с UI-элементом поиска.
2. Frontend реагирует на действие и формирует HTTP-запрос.
3. Браузер отправляет запрос на API-адрес.
4. API принимает запрос и шлёт его на backend.
5. Backend обрабатывает данные: проверяет параметры, ищет товары в базе.
6. Сервер возвращает ответ со статусом успеха (JSON с товарами).
7. JavaScript frontend получает ответ и обновляет визуальную структуру страницы.
8. Пользователь видит результаты поиска.

## 9. Вывод

В ходе лабораторной работы было проведено исследование HTTP-взаимодействия в веб-приложении Wildberries на выбранном сценарии «поиск товара и просмотр карточки». Было установлено, что интерфейс работает через клиентский JavaScript, который отправляет HTTP-запросы к серверу, а сервер отвечает данными и статусами выполнения операции.

Были выполнены следующие важные результаты:
- браузер и frontend тесно взаимодействуют для обработки пользовательского действия;
- запросы к API выполняются при загрузке страницы и при поиске;
- поиск товара сопровождается HTTP GET-запросом и ответом сервера;
- данные аналитики передаются через POST-запросы в зашифрованном виде;
- обратно пользователю приходит результат, который обновляет интерфейс без полной перезагрузки страницы.

Главный вывод состоит в том, что современное веб-приложение является распределенной системой: пользователь взаимодействует с UI, frontend формирует сетевые запросы, API организует обмен данными, а backend обрабатывает их и сохраняет состояние.
